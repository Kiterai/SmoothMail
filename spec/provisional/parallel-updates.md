# 並列更新の補完事項（未承認）

- `behavior.md`で承認済みのアカウント優先・残枠のフォルダ割当を適用する。既定4、入力範囲1～32。
  同じアカウントに対する別更新要求は対象別キューで直列化し、一つの更新内のフォルダを並列化する。
  フォルダ保留操作・MOVE・共通LISTの公開は先に直列実行する。
- 認証情報の取得待ちも実行枠に含める。待機中の更新は、現在のアカウント表示順で開始する。同じアカウント内は従来の対象別キューを維持する。
- 設定値を増やすと空き枠で待機要求を開始する。減らす場合は実行中の処理を中断せず、実行数が新しい上限未満になるまで追加を待つ。
- アカウント削除時はそのアカウントの認証・通信と待機要求だけを取り消す。取り消した通信が終了するまで、その実行枠は使用中とする。
- 折り畳みヘッダの再展開時は、直前のヘッダ高さを画面に収まる範囲で復元する。非展開時は基本情報・添付・展開ボタンを必要な高さに収め、残りの高さを本文に使う。
