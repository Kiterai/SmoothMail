## 更新方法

各詳細項目は、次の5項目をこの順番で記述する。条件付き動作や対応範囲の判断待ちも同じ形式とし、実装済みの動作を未実装と誤記しない。

```markdown
## ID: 項目名

- **対象仕様:** 根拠となる仕様へのリンクと対象範囲。
- **事情:** 仕様への対応や検証が完了していない理由・制約。
- **完了範囲:** 実装・検証済みの範囲と、その根拠となる資料へのリンク。
- **未完了範囲:** 残る実装・検証・承認事項。
- **完了条件:** 完了と判断できる具体的な条件。
```

資料は対応する欄に含め、詳細な調査・実験経緯は`agent/`、人向けの説明は`docs/`へリンクする。進展時は完了範囲・未完了範囲と確認日を更新し、完了した項目は根拠を付けて一覧から外す。利用者のメール、資格情報、登録JSONの内容や個人環境の絶対パスは記載しない。
