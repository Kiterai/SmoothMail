# 未完了・対応制約の一覧

仕様への対応や検証が完了していない項目だけを管理する。未実装、検証待ち、対応範囲・暫定方針の承認待ちを区別する。

## 実装上の制限・対応範囲の判断待ち

| ID | 項目 | 現在の状態 | 詳細 |
|---|---|---|---|
| LIMIT-01 | ページ外・別フォルダのスレッド解決 | ページ内表示は実装済み。アカウント全体の参照解決は未完了 | [制約](implementation-limits.md#limit-01-スレッドのページ境界) |
| LIMIT-02 | MOVE／UIDPLUS非対応サーバでのメール移動 | 保留操作を残してエラーとする。対応範囲の正式化待ち | [制約](implementation-limits.md#limit-02-サーバ機能による移動制限) |
| LIMIT-03 | アカウント間移動 | 未実装。対応範囲と安全な転送・復旧手順の判断待ち | [制約](implementation-limits.md#limit-03-アカウント間移動) |
| LIMIT-04 | 極端に大きい・深いMIME | 暫定上限で拒否。依存内部の資源制限・解析中断は未解決 | [制約](implementation-limits.md#limit-04-mimeの上限と解析耐性) |
| LIMIT-05 | 大規模SQL実行中の中断 | 古い結果の破棄は実装済み。SQL自体の途中停止は未対応 | [制約](implementation-limits.md#limit-05-大規模sqlの中断) |

フォルダ単独更新中の保留操作、トレイ非対応時の終了、並列更新の適用範囲は、[実装済みの暫定方針](implementation-limits.md#実装済みだが条件のある動作)の正式化待ちとして管理する。正式仕様に範囲がない制限を、直ちに仕様違反とは扱わない。未承認の補完方針は`spec/provisional/`に置く。

## 更新方法

詳細項目は次の5項目で統一する。

```markdown
## ID: 項目名

- **対象仕様:** 根拠となる仕様と対象範囲。
- **事情:** 対応や検証が完了していない理由。
- **完了範囲:** 当項目のうち実装・検証済みの範囲。
- **未完了範囲:** 残る実装・検証・承認事項。
- **完了条件:** 完了と判断できる具体的な条件。
```

完了した項目は本文・索引から完全に削除し、Git履歴だけに残す。当管理ディレクトリに完了一覧や代替記録は作らない。詳細な調査は`agent/`、現在の利用・開発手順は`docs/`に分け、秘密情報や個人環境の内容は記録しない。
