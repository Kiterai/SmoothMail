# 配布形態

## 共通注意事項

- 最終配布物にビルド作業者の個人情報・PC内情報が含まれないようにする。
- 指定プラットフォーム向けの最終配布物は、クリーンな状態のリポジトリ(cloneを行ったばかりの状態)から「.envファイルの記述」と「50文字以内の単一のコマンド実行」のみで完全に生成できるようにする。
    - コマンド実行の結果に以下の条件を要求する。
        - リリースビルドが達成され、それは docs/build.md に記述する手順に従った結果と一致すること。
        - ソフトウェアの動作および法的要件のクリアに必要な全ての配布物が揃うこと。
        - 配布物とは別に、直ちに起動できるバイナリが存在し、その内容が生成された配布物と一致していること。ここで「直ちに起動できる」とは、アーカイブの展開や必要ランタイムファイルの導入などの追加作業を一切必要としないことを意味する。
    - 以下に示す基本ツール・ライブラリの準備について、ビルド者の責務とすることを許容。
        - CMake
        - Git
        - Qt
        - Python
        - 各プラットフォーム向けコンパイラ/開発SDK
    - 生成された最終配布物の動作確認および法的監査については、配布作業者の責務とする。
    - ビルド手順については[docs.md](./docs.md)に基づき、適切に記述する。
- ライセンス的処理については、[license-handling.md](./license-handling.md)に基づいて注意深く行う。

## プラットフォーム別

- Windowsの場合
    - 単体で運搬して展開・実行可能なzip形式で配布する。
    - ZIPファイル内は以下のようなディレクトリ構造にする。
        - ライセンス情報ディレクトリ
        - runtimeディレクトリ: 必要ランタイム
            - DLL群など
            - Smoothmail.exe 本体
        - README.md : docs/usage.md と同内容
        - launch.cmd : runtimeディレクトリ内にある本体を呼び出す軽量なランチャー
    - MSVC CRTは、必要なRelease DLLを改変せずZIPへ同梱する。
