# SmoothMailのデータ保存領域

ZIPの展開先には本体・ライブラリ・ライセンス資料を配置します。メールや設定は展開先ではなく、実行中のOSユーザーの領域へ保存します。USB等でZIPを持ち運んでも、登録アカウントやメールキャッシュは一緒には移りません。

## Windowsでの保存先

| 保存先 | 内容 |
|---|---|
| `%LOCALAPPDATA%\SmoothMail\SmoothMail\smoothmail.sqlite` | アカウントのメールアドレス・接続設定、フォルダ、取得済みメール原文（本文・添付を含む）、検索索引、既読・重要等の状態、未同期の変更、ダウンロード履歴 |
| 同じディレクトリの`diagnostics\` | セッションごとの診断ログ、異常終了情報、実行中・異常終了を示すマーカー |
| レジストリ`HKEY_CURRENT_USER\Software\SmoothMail\SmoothMail` | 表示件数・列の並び／幅／ソート、自動更新周期・並列数、Google OAuthクライアントID等の設定（QtのQSettings） |
| OSの資格情報ストア（Windows資格情報マネージャー） | QtKeychain経由で保存するSMTP／IMAPのパスワード、OAuth更新トークンを含む認証情報、Google OAuthクライアントシークレット。サービス名は`SmoothMail` |
| OSで設定された「ダウンロード」フォルダ | 閲覧画面から保存した添付ファイル。同名ファイルは上書きせず連番を付ける |

`%LOCALAPPDATA%`は現在のユーザーのローカルアプリデータ領域です。保存先はOSの設定に従い、通常は`C:\Users\<ユーザー名>\AppData\Local`です。添付の保存先もOSのフォルダ設定に従うため、必ずしも`C:\Users\<ユーザー名>\Downloads`とは限りません。

本文・添付・メールアドレス等を保存するSQLite DBは、アプリ独自には暗号化しません。パスワード等をDBや設定へ平文で自動保存することはなく、OSストアへの保存に失敗した場合も平文へ切り替えません。ユーザー領域・バックアップのアクセス権と端末の保護を確認してください。

診断は処理段階・件数・エラーコード・モジュール内のコード位置等を記録し、メール本文や認証情報の記録を避ける設計です。ただし、共有前には記録内容を確認してください。通常のログはセッション単位で約4 MiBを超えると先頭へ戻って記録しますが、過去セッションのファイル全体を自動削除する仕組みではありません。

## バックアップ・移行

1. ウィンドウを閉じるだけでなく、トレイの**終了**から完全に終了します。
2. データ領域全体をコピーします。SQLiteの一時的な補助ファイルが存在する場合は、それらも含めて一緒に扱ってください。
3. 設定を残す場合は、上記レジストリのユーザー設定も別途保管します。
4. OS資格情報はDBのコピーには含まれません。別端末・別OSユーザーでは再登録・再認可が必要になる場合があります。認証情報を平文ファイルへ書き出さないでください。

保存した添付の実体はダウンロード先にあります。DB内のダウンロード履歴は実体のバックアップではありません。必要な添付ファイルは別途保管してください。新しい版でDB形式が更新される場合があるため、旧版へ戻す際は旧版に対応したバックアップを使用してください。

## 削除・初期化

- ZIPの展開先を削除しても、上記のユーザーデータ・設定・資格情報・保存済み添付は残ります。
- アプリ内でアカウントを削除すると、そのアカウントのローカル登録・キャッシュ・資格情報を除去します。サーバのメールや、保存済み添付の実体は削除しません。
- DB全体の削除は、取得済みメールだけでなく登録情報・履歴・**未同期の変更**も失う操作です。「キャッシュだけの消去」として扱わないでください。
- 完全な初期化が必要な場合は、終了・バックアップ後、対象ユーザーのデータ領域、上記設定、SmoothMailに属するOS資格情報をそれぞれ確認して削除します。他アプリの資格情報は削除しないでください。添付の実体は必要に応じて別途削除します。

macOS／Linuxの動作確認は未完了です。将来の各OS版ではQtの標準保存先を使用するため、Windowsのパスをそのまま適用しないでください。
