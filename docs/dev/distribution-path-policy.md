# 配布物のパス検査と供給元情報の扱い

2026-11-14、DIST-04の検査側対応を実装。Qt/SASLの外部配布物・上流由来の情報は保持してよいという利用者方針に従います。今回のビルド作業者の情報を許容するものではありません。

## 判定方法

`cmake/runtime-path-policy.json`は、由来を確認済みの11 DLL・15箇所だけを登録しています。

- Qt 6.12.0の10 DLL/プラグイン: SDK原本とSHA256一致・Authenticode Validを確認。供給元のPDB/ソース参照とQtCoreの固定temp値。
- Cyrus SASL 2.1.28の`libsasl.dll`: 上流`win32/include/config.h`の固定値`C:\CMU\bin\sasl2`。

各登録は相対ファイル名、ファイル全体のSHA256、許容するバイト範囲・そのSHA256・理由・由来を固定します。供給元の個人パス本文はポリシーへ転載しません。

検査は次の順序です。

1. Debug/ユーザーデータ混入、PE x64形式を従来どおり検査。
2. **元の全バイト**から入力root・作業者識別子を検査。供給元範囲内でも検出すれば拒否。
3. ポリシー対象は全体・範囲ハッシュを照合。不一致は停止して再レビューを要求。
4. 検査用メモリ上で許容範囲だけを隠し、それ以外を従来の絶対パス検査にかける。

DLL本体や署名は変更しません。ファイル名・署名だけによる一括除外ではなく、未登録DLL・許容範囲外のパスは引き続き拒否します。ZIP書込み時にも同じ検査とハッシュ照合を繰り返します。

## 実行

`PackageWindows.cmake`はリポジトリの固定ポリシーを自動で使用します。単独検査:

```bat
smoothmail_package.exe --audit-stage-with-policy <runtime> cmake/runtime-path-policy.json <workspace> <profile> <temp> <username> <computer-name>
```

従来の`--audit-stage`と`--package`はポリシーなしの厳格検査として残します。ポリシーは信頼されたビルド入力であり、配布物や外部から自動生成・自動承認しません。Qt更新・SASL再構築等でハッシュが変わった場合は、元供給物・署名・検出箇所・作業者情報非混入を確認してから更新します。検査エラーをなくす目的だけで登録しないでください。

## 確認結果

統合収集物`build/integrated-privacy-runtime`の39ファイルは新検査を通過しました。作業者profile/ユーザー名/PC名の追加照合0件、QtのSDK原本一致・署名Validは[前回記録](../../agent/integrated-runtime-builder-info-audit.md)のとおりです。

合成試験で、未登録・別名・バイナリ改変・範囲ハッシュ不一致・範囲外の追加パス・許容範囲内の作業者識別子・不正/重複ポリシーの拒否と、拒否時のZIP非公開を確認します。

これはパス検査の完了であり、DIST-02のlegal監査や、実ZIPのクリーン環境検証の完了ではありません。
