# 文書形式と自己完結した図表生成

対象: `f83bef8`、`e9c1ebe`、`5f2159a`、`c86bf59`、`spec/docs.md`。

## 図表・表記

- 表を1ソース1行へ変更し、クラス・グローバル関数・includeヘッダをセル内の`<br>`で改行する。クラスは短い名前、関数は名前だけを表示し、解析上の修飾名・シグネチャは維持する。
- architecture.mdはモジュール、外部依存、図、表、再生成方法、生成手法の順に整理した。図の直下に散在していた技術説明は最後の生成手法へ集約し、再生成方法には2行のコマンド以外を置かない。
- 本体と共通のターゲット宣言を`cmake/ApplicationTargets.cmake`へ分離した。通常ビルドは元のSTATIC／Qt executable・リンク・ソース設定を使う。文書専用設定だけは同じ宣言をINTERFACEモデルで評価し、ソースと種別のメタデータ、CMake Graphvizを取得する。
- 文書用の外部頂点は本体宣言の直接リンク先を表す。SDK内部の推移依存を読み込んだ実ビルド全体のグラフとは区別し、この範囲を生成手法に明記した。SDK・コンパイラ・Git・ライセンス監査処理を文書生成の前提にはしない。

## 自動導入

- `python tools/setup_architecture.py`で固定版のuv、専用Python 3.13.9、Doxygen 1.18.0、Graphviz同梱のPyGraphviz 2.0.4、Tree-sitter、Ninjaを`.cache/architecture/`へ導入する。手動の必須準備はPython 3.11以降とCMakeのみ。ホストPythonのpipやC++コンパイラも使わず、Pythonパッケージはwheelだけを導入する。
- uv 0.9.5とDoxygenの公式アーカイブはSHA256を固定し、取得物と展開済み実行ファイル／DLLを照合する。不一致・既存の不明な出力・unsafe tar/zipは上書きせず拒否する。uvのPython／wheelキャッシュと仮想環境はリポジトリ内へ隔離し、既存Qt・Python・PATH・ユーザー設定は書き換えない。
- `python tools/generate_architecture.py`は専用Pythonへ処理を引き継ぎ、SDK不要のCMake設定・Doxygen・Tree-sitter・Graphvizから図表を作る。表のマーカー内と8個の生成DOT／SVGだけを更新する。コンパイルやユーザーデータ操作は行わない。
- 実生成で使用した同梱Graphvizは14.1.5。画像素材は使用せず、すべてツールで生成した図である。Windows x64で初回導入・再導入・生成を確認した。Linux x64／macOS Intel・Apple Siliconの公式資産も定義したが、この環境ではそれらの実行検証はしていない。

## 検証

- 専用環境でPython試験34件成功。表の1行形式、修飾名／引数省略、文書順、再生成欄が2コマンドだけであること、アーカイブ逸脱／改変キャッシュ拒否を含む。
- 使用できないコンパイラ名とQtパスを指定した文書用CMakeテストでも構成が成功し、10ターゲット・アプリソースの収集とライセンス構築の非実行を確認した。
- 標準の2コマンドで専用環境を初回導入して図表を生成し、導入の再実行でも既存環境を再利用できた。
- 通常のMSVC Release構成を再設定・再構築し、アプリとテストEXEのリンクが成功した。既存CTest 24件も全件成功した。OS秘密情報への書込み等のopt-in試験のスキップを、実認証の確認とは扱わない。
- 製品ZIPのクリーン環境での通し再検証は別のBATCH-01を維持する。
